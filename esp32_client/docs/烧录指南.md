# ESP32-S3-CAM 烧录与部署指南

> 适用板子：**ESP32-S3-CAM（N16R8：16MB Flash / 8MB PSRAM）**，运行 MicroPython。
>
> ⚠️ 屏幕 ST7789 占用了 GPIO43/44（板载 **TTL-USB 串口**），所以**烧录 / REPL / 文件传输一律走 OTG USB-C 口**；烧录时**拔掉电池**，仅用 USB 供电。

---

## 0. 前置准备

1. **安装 mpremote**（文件传输 / REPL，日常用得最多）：
   ```bash
   pip install mpremote
   ```
2. **安装 esptool**（只在刷固件时需要）：
   ```bash
   pip install esptool
   ```
3. **连接板子**：OTG USB-C 口插电脑，在「设备管理器 → 端口(COM 和 LPT)」确认端口号（下面以 `COM4` 为例）。
   查看可用端口：
   ```bash
   mpremote connect list
   ```

---

## 1. 烧录固件（首次 / 换固件时）

1. 下载 MicroPython **ESP32-S3** 固件（N16R8 版本），建议使用带 **st7789 / esp32-camera / sdcard** 驱动的固件。
2. 擦除 Flash：
   ```bash
   esptool.py --chip esp32s3 --port COM4 erase_flash
   ```
3. 写入固件（偏移 `0x0`）：
   ```bash
   esptool.py --chip esp32s3 --port COM4 --baud 460800 write_flash -z 0x0 固件文件名.bin
   ```
4. 验证：重插 USB，`mpremote connect COM4 repl`，回车看到 `>>>` 即成功（`Ctrl+]` 退出 REPL）。

## 2. 上传项目文件

### 2.1 设备端目录结构（目标状态）

```
/（根目录）
├── boot.py      # 开机自动执行：连接 WiFi（⚠️ 必须放在根目录才生效）
├── main.py      # 开机自动执行：启动主程序（可选，见 2.3）
└── src/         # 项目包
    ├── main.py
    ├── logger.py
    ├── utils.py
    └── actors/
        ├── __init__.py
        ├── base.py
        ├── brain.py
        ├── micro.py
        └── speaker.py
```

### 2.2 上传命令

> `mpremote fs cp -r` 没有「排除指定目录」的功能，而 `__pycache__` 是你**在 PC 上跑 CPython 时**生成的缓存（MicroPython 在设备上不生成、也不需要它）。所以上传前先清一下：

```bash
# 0)（推荐）清理 src/ 下的 __pycache__ 缓存
Get-ChildItem src -Recurse -Directory -Filter __pycache__ | Remove-Item -Recurse -Force
# 或者（跨平台用 Python）：
python -c "import shutil, pathlib; d = list(pathlib.Path('src').rglob('__pycache__')); [shutil.rmtree(p) for p in d]; print('removed %d __pycache__' % len(d))"

# 1) boot.py → 设备根目录（冒号 : 表示根目录；源文件在仓库 src/boot.py）
mpremote connect COM4 fs cp src/boot.py :

# 2) src/ 整个包 → 设备 /src（-r 递归拷贝目录）
mpremote connect COM4 fs cp -r src :

# 3)（可选）开机自启入口 main.py → 根目录（内容见 2.3）
mpremote connect COM4 fs cp main.py :

# 4) 验证文件是否到位
mpremote connect COM4 fs ls
mpremote connect COM4 fs ls src/
```

> 若已上传过旧版本，设备端残留的 `__pycache__` 可用 `mpremote connect COM4 fs rm -r src/__pycache__` 删掉（或直接重新上传覆盖）。

> ⚠️ `boot.py` 在仓库里位于 `src/` 下，但 MicroPython **只在根目录找 `/boot.py`**。`src/boot.py` 不会被自动执行，必须用上面第 1 条命令把它拷到根目录。

### 2.3 根目录 `main.py`（开机自启用，内容如下）

```python
try:
    import asyncio
except ImportError:
    import uasyncio as asyncio

from src.main import main

asyncio.run(main())
```

> **MicroPython 开机顺序**：`boot.py`（连 WiFi）→ `main.py`（启动主程序）。
> 放好根目录 `main.py` 后，用 [3.1 的 `mpremote connect COM4 reset`](#31-一键运行主程序推荐) 一键启动。
>
> 💡 调试期建议**先别放根目录 main.py**，用手动方式跑（见 3.3），避免设备一上电就卡在主程序里，REPL 都进不去。

### 2.4 无线上传（WebREPL，免 USB 线）

> mpremote（含 1.28）**只支持串口传输**，不支持 websocket 连接。网络上传用仓库里的 `webrepl_tool.py`（跨平台，cmd/PowerShell 都能跑）或官方 `webrepl_cli.py`（来自 [github.com/micropython/webrepl](https://github.com/micropython/webrepl)）。

**一次性准备**（首次还是需要插一次 USB）：

1. 启用 WebREPL：REPL 里执行 `import webrepl_setup` → 按提示设密码、选开机自启 → 设备重启
2. 在 `src/boot.py` 末尾加（已含，见仓库）：
   ```python
   import webrepl
   webrepl.start()
   ```
3. 查设备 IP：`import network; print(network.WLAN(network.STA_IF).ifconfig()[0])`

**之后免线更新**（PC 与设备同一网络；脚本会自动在设备上建目录）：

```bash
# 整目录上传 + 更新根目录 boot.py（推荐：单次连接、跳过 __pycache__、自动建目录）
python webrepl_tool.py upload -H 192.168.0.105 -P 1234 --boot

# 只传代码（boot.py 不动）
python webrepl_tool.py upload -H 192.168.0.105 -P 1234

# 拉取设备日志到本地（/logs 目录）
python webrepl_tool.py getlogs -H 192.168.0.105 -P 1234

# 下载设备任意文件/目录（--src 设备路径，--remote 本地位置）
python webrepl_tool.py get -H 192.168.0.105 -P 1234 --src /logs --remote dl_logs

# PowerShell 版脚本（可选）
.\upload_wifi.ps1 -Device 192.168.0.105 -Password 1234

# 单文件上传
python webrepl_cli.py -p 你的密码 src/main.py 192.168.0.105:/src/main.py

# 从设备下载（如日志）
python webrepl_cli.py -p 你的密码 192.168.0.105:/logs/micro.log .

# 网页版客户端（零安装）：浏览器打开 https://micropython.org/webrepl/ → 地址填 192.168.0.105:8266
```

> ⚠️ MicroPython 的 WebREPL 是**单连接**服务器：上传前先关掉浏览器里开着的 WebREPL 页面，否则新连接会排队等到超时。

> 🔒 `webrepl_cli.py` 与 `upload_wifi.ps1` 里都带明文密码（`-p` 参数），注意别把密码提交进 git。

## 3. 运行与调试

### 3.1 一键运行主程序（开机自启，推荐）

上传好根目录 `main.py` 后，**一条命令软复位即启动**（自动执行 `boot.py → main.py`）：

```bash
mpremote connect COM4 reset
```

> 程序会**常驻运行**（机器人是活的）；`Ctrl+C` 中断当前程序，`Ctrl+]` 退出 mpremote。
> 若还没有根目录 `main.py`，这条命令只会重启到 REPL，不会启动主程序。

### 3.2 快速运行主程序（调试期，不用进 REPL）

前提：`src/` 已上传到设备（见 2.2）。在**仓库根目录**执行：

```bash
mpremote connect COM4 run run_device.py
```

> `run_device.py` 是仓库根目录下的启动器，只用了绝对导入，`mpremote run` 可以直接执行它，程序常驻运行。
>
> ⚠️ 直接 `mpremote run src/main.py` 会报 **`ImportError: can't perform relative import`**：
> `mpremote run` 是**单文件**执行，没有包上下文，`main.py` 里的 `from .xxx` 相对导入必然失败。

### 3.3 手动运行（备用，进 REPL 手敲）

```bash
mpremote connect COM4 repl
```

`Ctrl+D` 软复位（会重跑 `boot.py → main.py`），`Ctrl+]` 退出；或直接：

```python
>>> import asyncio
>>> import src.main
>>> asyncio.run(src.main.main())
```

### 3.4 单文件测试（不依赖包导入的脚本）

```bash
mpremote connect COM4 run test.py
```

### 3.5 查看 / 拉取日志

设备日志统一写在 `/logs/` 目录（UTF-8）：

```bash
mpremote connect COM4 fs cp :logs/micro.log ./micro.log
mpremote connect COM4 fs cp :logs/main.log  ./main.log
```

## 5. 常见问题

| 现象 | 原因 / 解决 |
|---|---|
| 找不到 COM 口 / 连不上 | 确认走 **OTG USB-C 口**（TTL 口被屏占了）；换数据线 / 换 USB 口；重插后看设备管理器 |
| `ImportError: can't perform relative import` | 直接 `mpremote run src/main.py` 所致：mpremote 单文件执行没有包上下文。改用 `mpremote run run_device.py`（见 3.2） |
| 开机卡死、REPL 没反应 | 多半是 `boot.py` 里 WiFi **死等**：连不上就 `while` 死循环。建议加超时（见下方代码） |
| 端口被占用 | 板子若已连着其它串口工具（Thonny / putty），先关掉 |
| 上传后中文乱码 | 日志文件是 UTF-8，用支持 UTF-8 的编辑器查看；`boot.py` 里的中文注释在串口可能显示乱码，属正常 |

## 附：mpremote 命令速查

| 命令 | 作用 |
|---|---|
| `mpremote connect list` | 列出可用串口 |
| `mpremote connect COM4 repl` | 进入 REPL（`Ctrl+D` 软复位，`Ctrl+]` 退出） |
| `mpremote connect COM4 reset` | 软复位：重跑 boot.py → main.py（即"运行 main"） |
| `mpremote connect COM4 exec "语句"` | 在设备上执行单条语句（如 `exec "import main"`） |
| `mpremote connect COM4 fs cp 本地文件 :` | 上传文件到根目录 |
| `mpremote connect COM4 fs cp -r 目录 :` | 递归上传目录 |
| `mpremote connect COM4 fs cp :远端文件 ./` | 下载设备文件 |
| `mpremote connect COM4 fs ls` | 列出根目录 |
| `mpremote connect COM4 fs rm 文件` | 删除设备文件 |
| `mpremote connect COM4 run run_device.py` | 运行主程序（调试期最快方式，src/ 已上传即可） |
| `mpremote connect COM4 run 脚本.py` | 在设备上执行单个脚本 |
